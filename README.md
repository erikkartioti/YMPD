# ympd

Скачивает плейлист из Яндекс Музыки в lossless (FLAC/WAV) через [Soulseek](https://www.slsknet.org/) с помощью [slskd](https://github.com/slskd/slskd).

Скрипт сам ищет каждый трек, отбирает подходящие файлы, ставит лучший в загрузку и **переключается на следующий вариант**, если загрузка отклонена, оборвана, не началась или идёт слишком медленно. Треки, которые найти не удалось, попадают в `not_found.json` с указанием причины.

## Как это работает

```
плейлист Яндекс Музыки
        │  (yandex-music)
        ▼
запрос «исполнитель название» ──► поиск в slskd (slskd-api)
        │
        ▼
отбор файлов: lossless, размер, очередь, слова запроса целыми словами,
без live/remix/edit и т. п. ──► список вариантов, отсортированный по рейтингу
        │
        ▼
загрузка лучшего варианта ──► опрос статусов раз в несколько секунд
        │
        ├─ Completed, Succeeded ─────────────► готово
        ├─ Rejected / Aborted / Errored /
        │  TimedOut / Cancelled ─────────────┐
        ├─ не началась за N секунд ──────────┼─► отмена и следующий вариант
        └─ скорость ниже порога M секунд ────┘
                                              │ варианты кончились
                                              ▼
                                       not_found.json
```

### Рейтинг вариантов

Файлы сортируются по ключу: оценка файла → свободный слот у раздающего → короче очередь → выше скорость аплоада. В оценку файла входят: разрядность 24 бит (+100), источники `web`/`qobuz`/`tidal` (+30), пометка `[cd]`/`[flac]` (+10), формат FLAC (+5), префикс `@@` (−20). Веса лежат в `search.py::file_score`.

## Установка

Нужен Python 3.9+ и запущенный [slskd](https://github.com/slskd/slskd) с включённым API-ключом (раздел `web.authentication.api_keys` в конфиге slskd).

```bash
git clone https://github.com/<user>/ympd.git
cd ympd
python -m venv .venv && source .venv/bin/activate
pip install -e .
cp .env.example .env   # и заполните значения
```

Токен Яндекс Музыки получают способом, описанным в документации библиотеки [yandex-music](https://github.com/MarshalX/yandex-music-api). Получить токен можно через ympd_get_token.py
## Использование

```bash
ympd --playlist 145932cb-b034-b3e7-8e3b-0af57fa46230
ympd --playlist https://music.yandex.ru/playlists/<uuid>
ympd --dry-run          # только поиск и отбор, без загрузки
python -m ympd -v       # то же через модуль, с подробными логами
```

Плейлист можно задать флагом или переменной `YANDEX_PLAYLIST` в `.env`. Повторный запуск безопасен: уже выполненные поиски переиспользуются, а уже скачанные файлы не ставятся в очередь заново.

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--playlist` | из `.env` | UUID или ссылка на плейлист |
| `--report` | `not_found.json` | куда сохранить отчёт |
| `--dry-run` | выкл. | только поиск и отбор вариантов |
| `--max-queue` | 5 | максимальная очередь у раздающего |
| `--max-candidates` | 10 | запасных вариантов на трек |
| `--start-timeout` | 150 | секунд до переключения, если загрузка не началась |
| `--min-speed` | 50 | КБ/с: медленнее считается слишком медленной |
| `--slow-grace` | 40 | секунд медленной загрузки до переключения |
| `-v` | выкл. | подробные логи |

Остальные пороги (`appear_timeout`, `near_done`, список исключений и др.) лежат в `config.py::Settings`.

## Отчёт `not_found.json`

```json
{
  "generated_at": "2026-11-07T12:00:00+00:00",
  "not_found": [
    {"artist": "…", "title": "…", "query": "…", "reason": "no_response"},
    {"artist": "…", "title": "…", "query": "…", "reason": "all_failed",
     "attempts": ["user1: Rejected", "user2: медленно (3 КБ/с)"]}
  ],
  "done": ["…"]
}
```

Причины: `no_response` — на запрос никто не ответил; `no_match` — ответы есть, но подходящих файлов нет; `all_failed` — все варианты провалились (в `attempts` лог по каждому).

## Структура

```
src/ympd/
  cli.py        аргументы, сборка пайплайна
  config.py     Settings (пороги) и загрузка .env
  models.py     Track, Candidate, Job
  yandex.py     чтение плейлиста
  search.py     поиск в slskd, отбор и рейтинг вариантов
  downloads.py  постановка в очередь, мониторинг, переключение вариантов
  report.py     not_found.json
tests/          pytest; slskd заменён заглушкой, сеть не нужна
```

## Ограничения

- Совпадение ищется по словам запроса в пути файла. Если файлы подписаны иначе (транслит, другое написание), трек попадёт в `not_found.json`.
- Состояния загрузок (`Completed, Rejected` и т. д.) соответствуют текущему API slskd; при смене формата ответов логика в `downloads.py::step` может потребовать правки.
- Soulseek зависит от того, кто сейчас онлайн: треки из `not_found.json` имеет смысл искать повторно позже.

## Дисклеймер

Инструмент автоматизирует поиск и загрузку через клиент slskd. Используйте его только для музыки, которую вы вправе скачивать и хранить по законам вашей страны и правилам площадок. Проект не связан с Яндексом, Soulseek и slskd.
